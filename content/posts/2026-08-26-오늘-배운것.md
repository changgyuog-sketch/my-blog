클로드 코드와 함께 이 블로그를 만들면서, 프레임워크 없이 순수
HTML/CSS/JavaScript만으로도 각자의 역할을 명확히 나누면 충분히 깔끔한
결과물이 나온다는 걸 배웠다. 오늘 배운 내용을 간단히 정리해본다.

## HTML — 구조를 담당

- HTML은 페이지의 뼈대다. `header`, `main`, `article`, `footer` 같은
  태그로 콘텐츠의 의미를 나눈다.
- 템플릿 파일(`templates/post.html`, `templates/index.html`)에는
  `{{title}}`, `{{content}}` 같은 자리표시자만 넣어두고, 빌드 스크립트가
  실제 값으로 치환해서 최종 HTML을 만든다.
- 마크다운 본문도 결국 빌드 과정에서 `<h2>`, `<ul>`, `<pre><code>` 같은
  평범한 HTML로 변환되어 템플릿 안에 끼워진다.

## CSS — 스타일, 다크모드, 반응형을 담당

- 색상을 CSS 변수(`:root`)로 한 곳에 모아두면 다크모드 전환이 훨씬
  쉬워진다. 라이트/다크 각각 변수 값만 바꿔주면 되기 때문이다.
- `prefers-color-scheme` 미디어 쿼리로 시스템 다크모드를 자동 감지하고,
  `data-theme` 속성으로 사용자가 수동으로 오버라이드할 수 있게 했다.
- 좁은 화면에서는 미디어 쿼리로 폰트 크기와 여백을 줄여서 모바일에서도
  읽기 편하게 만들었다.
- 코드블록에는 `overflow-x: auto`를 줘야 긴 코드가 있어도 모바일
  화면이 가로로 밀리지 않는다.

## JavaScript — 아주 작은 상호작용만 담당

- 페이지 렌더링 자체는 빌드 타임에 이미 끝나 있어야 하고, 브라우저에서
  실행되는 JS는 다크모드 토글 버튼 클릭 같은 최소한의 상호작용만
  처리하면 된다.
- 사용자가 고른 테마는 `localStorage`에 저장해서 다시 방문했을 때도
  유지되게 했다.
- `<head>`에 아주 작은 인라인 스크립트를 넣어, CSS가 그려지기 전에
  저장된 테마를 먼저 적용했다. 이렇게 하지 않으면 페이지가 라이트
  모드로 잠깐 번쩍였다가 다크모드로 바뀌는 현상(FOUC)이 생긴다.
- 빌드 스크립트(`build.js`, Node.js 환경)와 브라우저에서 실행되는
  코드(`main.js`)는 역할이 완전히 다르다는 것도 다시 확인했다.
  `fs`, `path` 같은 Node 전용 API는 브라우저용 JS에 절대 들어가면
  안 된다.

## 느낀 점

프레임워크가 없어도 "HTML은 구조, CSS는 표현, JS는 최소한의 상호작용"
이라는 원칙만 지키면 충분히 유지보수하기 쉬운 결과물을 만들 수 있다는
걸 몸으로 확인한 하루였다.
